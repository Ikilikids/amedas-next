# 気候解説データ作成規定（Climate Article Guidelines）

地域（Region）および都道府県（Pref）の気候解説データを作成・編集する際は、以下のルールを厳格に遵守すること。

---

## 1. 文体・表現方針【最重要・厳守】

解説文は**「純粋な気象データ・地理的事実に基づく客観的な解説」**に徹すること。主観、情緒、生活感、防災喚起、メディア的誇張は一切持ち込んではならない。

### ① 情緒的・文学的・旅行ガイド的フレーズの完全禁止
- **NG例**: 「黒潮洗う」「肌で感じられます」「雄大な山々」「水資源の宝庫」「〜の恩恵を受け」
- **改善**: 「黒潮の影響により」「南北での気温差が顕著」「年間降水量が多く」など、客観的な気象表現に置き換える。

### ② 生活・社会・防災喚起表現の排除
- **NG例**: 「火災予防の警報が出るほど」「〜への備えが日常的に求められます」「人々の生活を支える」「水不足に悩まされ」
- **改善**: 「湿度が著しく低下する」「年間降水量が極めて少ない」など、社会的影響ではなく気象現象そのものを記述する。

### ③ メディア的通念・誇張表現の排除と実態の正確な限定
- **NG例**: 「東京は夏季の熱帯夜日数が全国トップクラス」（※実際は沖縄・九州・近畿など西日本の方が圧倒的に多い）
- **改善**: 根拠のない「全国トップクラス」などの誇張を排し、「周辺の関東内陸部と比べると夜間の気温が下がりにくく」のように、客観的データに基づき比較対象を正しく限定して記述する。

---

## 2. ディレクトリ構成・ファイル命名規則【厳守】

気象庁コードおよび地方番号に準拠し、北から南へ正しく整列するファイル構造を維持する。

### ① 地域データ（`src/data/regions/`）
北から順に地方番号を付与したファイル名とする。
* `1_hokkaido.ts`
* `2_tohoku.ts`
* `3_kanto.ts`
* `4_hokuriku.ts`
* `5_chubu.ts`
* `6_kinki.ts`
* `7_chugoku.ts`
* `8_shikoku.ts`
* `9_kyushu.ts`
* `10_okinawa.ts`

### ② 都道府県データ（`src/data/prefs/`）
地方ごとの番号付きフォルダ内に、気象庁府県予報区コード付きの単一ファイルとして配置する。
* **フォルダ名**: `1_hokkaido/`, `2_tohoku/`, `3_kanto/` ... `10_okinawa/`
* **ファイル名**: `[気象庁コード]_[ローマ字名].ts`（例: `43_saitama.ts`, `44_tokyo.ts`）
* **index.ts**: 各地方フォルダ内に必ず配置し、配下の県ファイルを一括再エクスポートする。

## 3. データ構造（ClimateArticleData / ClimateSection）

気候解説文は、フラットな文字列ではなく `ClimateSection[]` 構造で定義する。

```typescript
export interface ClimateSection {
  title?: string;       // セクション見出し（例: "全体の特徴", "北部平野部" など）
  content: string[];    // 文章の配列。1文（「。」）ごとにカンマ区切りで改行記述
  isSummary?: boolean;  // 上位階層の簡易要約として採用する場合は true
}
```

---

## 4. 階層構造とセクション区分ルール

### ① 地域（Region）の構成規則
- **中間区分が存在する地域（東北、関東、中部、近畿、中国、四国、九州）**:
  - 全体の特徴セクション（`isSummary: true`）に加え、東西・南北などの主要な中間区分（例: 日本海側/太平洋側、山陰/山陽など、`isSummary: false`）を作成・記述する。
- **中間区分が存在しない地域（北海道、北陸など）**:
  - 中間レベルの `description` は設けず、「全体の特徴（`isSummary: true`）」の単一セクション（1階層）でまとめる。

### ② 都道府県（Pref）の構成規則
- **先頭セクション**: 必ずその都道府県の「全体の特徴（`isSummary: true`）」とし、地方詳細ページ等で要約として引用される前提で簡潔にまとめる。
- **配下セクション**: 県内の主要気候エリア（平野・内陸盆地・山岳部など、`isSummary: false`）を2〜3区分程度で記述する。
- **島嶼部の扱い**: 東京都などの本土気候解説においては、島嶼部（伊豆・小笠原など）は除外し、本土の気候特性に特化して記述する。

## 5. 3階層の表示制御ルール（isSummaryの役割）

気候解説はサイト内で以下の3階層に分かれて表示される。`isSummary` フラグにより上位階層の表示内容を自動制御する。

| 階層 | URL | 表示内容 | 表示形式 |
| :--- | :--- | :--- | :--- |
| **第1階層** | `/feature/region` (全国一覧) | 各地方の `isSummary: true` のセクションのみ | 見出しなし・1段落の簡潔な要約文 |
| **第2階層** | `/feature/region/[region]` (地方詳細) | ① 当該地方の全セクション<br>② 配下各県の `isSummary: true` のみ | ① 【見出し】＋各段落で詳細表示<br>② 見出しなし・各県の簡潔な要約文 |
| **第3階層** | `/feature/region/[region]/[pref]` (都道府県詳細) | 当該都道府県の全セクション | 【見出し】＋各段落で詳細表示 |

---

## 6. ハイライト（highlights）の文字数・連動規定【厳守】

- 各項目の文字列長は **20文字以内** とすること。
  - バッジやグリッド表示で文字あふれ・改行崩れを防ぐため、簡潔かつ端的なキーワード・フレーズでまとめる。
  - OK例: `熊谷を中心とする全国屈指の猛暑記録`（18文字）
  - NG例: `冬の日本海側の豪雪と十勝平野の快晴（十勝晴れ）`（23文字 ✕）
- **本文（content）との厳密な連動**:
  - 本文側で記述を削除・変更した要素（例: やませの削除等）は、ハイライト側にも残さず必ず連動して修正すること。

---

## 7. コード可読性・エディタ表示ルール【厳守】

- **横スクロールの禁止**:
  - 1行に長文をベタ書きしない。
  - `content` の配列内で、**1文（「。」）ごとに要素を区切ってカンマ改行**すること。
  - `+` による不自然な文字列結合は避け、配列要素として分割すること。
- **既存設定の尊重**:
  - 既存のUIスタイル、マージン、余白を勝手に変更しない。
- **不要なコマンド実行の禁止**:
  - ユーザーからの明示的な指示がない限り、バックグラウンドでのビルドや型チェック（`tsc`）、`git` コマンド等を勝手に実行しない。
