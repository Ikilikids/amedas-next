# 気候解説データ作成規定（Climate Article Guidelines）

地域（Region）および都道府県（Pref）の気候解説データを作成・編集する際は、以下のルールを厳格に遵守すること。

---

## 1. データ構造（ClimateArticleData / ClimateSection）

気候解説文は、フラットな文字列ではなく ClimateSection[] 構造で定義する。

`typescript
export interface ClimateSection {
  title?: string;       // セクション見出し（例: "全体の特徴", "北関東（内陸部）" など。省略可）
  content: string[];    // 文章の配列。1文ごとにカンマ区切りで記述すること
  isSummary?: boolean;  // 上位階層の簡易要約として採用する場合は true
}
`

### 必須フィールド構成例
`typescript

## 2. 3階層の表示制御ルール（isSummaryの役割）

気候解説はサイト内で以下の3階層に分かれて表示される。isSummary フラグにより上位階層の表示内容を自動制御する。

| 階層 | URL | 表示内容 | 表示形式 |
| :--- | :--- | :--- | :--- |
| **第1階層** | /feature/region (全国一覧) | 各地方の isSummary: true のセクションのみ | 見出しなし・1段落の簡潔な要約文 |
| **第2階層** | /feature/region/[region] (地方詳細) | ① 当該地方の全セクション<br>② 配下各県の isSummary: true のみ | ① 【見出し】＋各段落で詳細表示<br>② 見出しなし・各県の簡潔な要約文 |
| **第3階層** | /feature/region/[region]/[pref] (都道府県詳細) | 当該都道府県の全セクション | 【見出し】＋各段落で詳細表示 |

- **isSummary: true のセクション**:
  - その地域・都道府県を代表する「全体の特徴」を1つだけ設定する（通常は先頭セクション）。
  - 上位階層では見出し（	itle）は表示されず、本文のみが連結されて簡潔な要約文として使われる。
- **isSummary: false のセクション**:
  - 詳細ページでのみ表示される地域内のエリア別解説（内陸・沿岸・山間部など）。

---

## 3. ハイライト（highlights）の文字数規定【厳守】

- 各項目の文字列長は **20文字以内** とすること。
  - バッジやグリッド表示で文字あふれ・改行崩れを防ぐため、簡潔かつ端的なキーワード・フレーズでまとめる。
  - OK例: 梅雨が存在しない爽やかな夏（13文字）、内陸盆地で氷点下30℃級の極寒（15文字）
  - NG例: 冬の日本海側の豪雪と十勝平野の快晴（十勝晴れ）（23文字 ✕）

---

## 4. Regionの階層構造と description 記述規則

- **中間区分あり（例: 関東 `kanto`）**:
  - 関東地方のように全体と各県の間に「北関東・南関東」という中間グループが存在する地域では、全体の特徴セクション（isSummary: true）に加えて、中間区分（北関東・南関東）の `description` セクションも作成・記述する。
- **中間区分なし（例: 北海道 `hokkaido`）**:
  - 北海道と細分エリア（道東・道北・道央・道南等）の間に中間グループが存在しない地域では、中間レベルの `description` は設けず、直下の細分エリアに直接繋げる構成とする。

---

## 5. コード可読性・エディタ表示ルール【厳守】

- **横スクロールの禁止**:
  - 1行に長文をベタ書きしない。
  - content の配列内で、**1文（「。」）ごとに要素を区切ってカンマ改行**すること。
  - + による不自然な文字列結合は避け、配列要素として分割すること。
- **既存設定の尊重**:
  - 既存のUIスタイル、マージン、余白を勝手に変更しない。
  - 不要な文章の削除指示があった場合は、本文（content）だけでなくポイント（highlights）側の記述との整合性も確認する。
