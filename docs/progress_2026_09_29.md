# 開発記録・本日の進捗まとめ

## 1. 気候データ統合パイプラインの全面刷新

### 背景と目的
- 従来は SSG 時に全67項目を一括計算（`loadAllMetrics`）しており、メモリ消費とビルド時間が課題だった。
- ページによって必要な気象項目（雨温図用6項目、星取表用6項目、バッジ用6項目など）が異なるため、必要なメトリックのみをオンデマンドで取得できるアーキテクチャへと刷新。
- `ssgLoader.ts` 内に独自で存在していたランキング集計コード（約200行）を撤廃し、一元化された統合パイプラインからバッジ・ランキングを導出するようにリファクタリング。

### 実装内容
1. **`src/setting/assemble.ts` の新設**
   - 描画ターゲット（`uonzu`, `stars`, `badge`, `overview`, `table`, `ratio`）と、各ターゲットに必要な気象項目（`metrics`）を設定として一元管理。
   - `resolveRequiredMetrics(options)` により、要求されたターゲットに必要なメトリック群を重複なく自動抽出。
2. **`src/utils/climateDataManager.ts` の改修**
   - 旧 `loadAllMetrics()`（全67項目一括計算）を完全削除。
   - `getStationMetrics(stationIds?, options?, customMaster?)` を刷新。
     - 返り値を配列から辞書（`Record<StationId, FullStationData>`）に統一。
     - 指定された `options` に応じて必要な気象項目のみをオンデマンド読み込み。
     - ブラウザ環境（Client）とサーバー環境（SSG）の双方で同一インターフェースで動作。
3. **`src/utils/ssgLoader.ts` の重複コード削除**
   - `getMetricRanks()` などの独自 JSON 読込・ソート集計を完全削除。
   - `getStationMetrics` が算出した `badge`（順位・値を保持）から直接抽出する `extractRainbowStations` / `extractTop1Stations` に置き換え。
4. **型定義・ロジックの補強**
   - `RawBadgeData` に `place`（順位）と `value`（値）を追加し、バッジ情報からそのままランキング値を利用可能に。
   - `RawData` に `stars` を正式統合。

## 2. Next.js 16 / Turbopack / Webpack 競合の解消

### 発生した問題
- Next.js 16.2.6 では `next build` がデフォルトで Turbopack を使用するよう仕様変更された。
- プロジェクト内のカスタム Webpack 設定（`next.config.mjs`）と競合し、ビルド時に以下のエラーが発生：
  ```text
  ⨯ ERROR: This build is using Turbopack, with a webpack config and no turbopack config.
  ```

### 対応
- `package.json` の `build` スクリプトに `--webpack` フラグを明示（`next build --webpack`）。
- `dev` 側は高速な Rust 製 Turbopack（`next dev`）を活かせるよう、`next.config.mjs` に Turbopack 用の `resolveAlias`（ブラウザ側での `fs` / `path` 空モジュール差し替え）を設定。

## 3. クライアント側での 404 エラー（不要なJSONリクエスト）の解消

### 発生した問題
- 地点比較ページ（`/compare`）を開いた際、ブラウザのコンソールおよびサーバーログに存在しないランキング JSON（`max_hitemp.json`, `min_lwtemp.json` 等）への 404 エラーが大量発生。

### 原因
- `useRankingData.ts` の `useStationDetail` 内で `getStationMetrics` を呼ぶ際、`options` を渡していなかったため、デフォルトの「全67項目」を読み込もうとしていた。

### 対応
- `src/components/Ranking/useRankingData.ts` を修正：
  ```ts
  const metricsMap = await getStationMetrics(
    [stationId],
    { overview: true, uonzu: true, badge: true },
    master
  );
  ```
- 必要なターゲット（雨温図・概況・バッジ）のみを指定することで、不要な 404 リクエストを完全に防止。

## 4. 本番 Node サーバー起動時（`npm run start`）の 500 エラー根本解消

### 発生した問題
- `npm run build` は成功するものの、standalone サーバー起動（`npm run start`）時に、地点詳細ページ等で 500 エラーが発生：
  ```text
  Cannot find module '.../reselect/dist/reselect.mjs' imported from .../@reduxjs/toolkit/dist/redux-toolkit.modern.mjs
  Did you mean to import "reselect/dist/cjs/reselect.cjs"?
  ```

### 原因の特定
- グラフライブラリ `recharts`（v3）が内部で依存する Redux Toolkit / Reselect が、Node.js の厳格な ESM 解決に対応していない形式（拡張子省略インポート等）を含んでいた。
- サイト全体で唯一 `recharts` を使用している円グラフコンポーネント（`ChartPieSection.tsx`）がサーバーサイドレンダリング（Node.js / SSG）のバンドルに含まれていたため、サーバー起動時に Node.js が ESM の解釈に失敗していた。

### 解決策
- **`src/components/LayeredPieChart/index.tsx`**:
  `ChartPieSection` を `next/dynamic`（`ssr: false`）に変更：
  ```tsx
  const ChartPieSection = dynamic(() => import("./ChartPieSection"), {
    ssr: false,
  });
  ```
- **効果**:
  - サーバー（Node.js）上では `recharts` / `redux` / `reselect` が一切読み込まれず、ブラウザ（クライアント）でのみ実行される。
  - サーバー側でのモジュール未検出・ESM 解決失敗（500エラー）を物理的に根絶。
  - `npm run build`（全1333ページ SSG）もエラー0で完全通過。
